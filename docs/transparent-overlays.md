# bilimaku 透明悬浮组件

## 1. 模块边界

本版包含两个独立 Tauri Webview 窗口：

- `danmaku-overlay`：全屏透明、置顶、默认鼠标穿透；接收到事件后按轨道从右向左滚动。
- `event-sidebar`：纯透明侧边事件流、置顶、可放在屏幕左侧或右侧；没有事件时不绘制任何可见背景，收到事件后才显示独立气泡。

两个窗口各自订阅统一的 `live://event` 领域事件，彼此不引用组件状态。主窗口只负责保存设置、开关窗口与发送预览事件。设置通过 `overlay://settings` 广播，预览通过 `overlay://preview` 广播。

```text
Web Live Adapter ── live://event ──┬── 全屏滚动弹幕窗口
                                   └── 侧边事件窗口

主窗口参数面板 ─ overlay://settings ──> 两个独立窗口
主窗口预览按钮 ─ overlay://preview  ──> 两个独立窗口
```

## 2. 全屏滚动弹幕参数

- 事件类型：弹幕、互动、礼物、SC、大航海、系统；
- 昵称、昵称色（默认 #66CCFF）、头像与鼠标穿透开关；
- 每一种事件的独立颜色；
- 字体族、字号、粗细、整体不透明度；
- 描边颜色、描边宽度、阴影颜色、阴影模糊；
- 按像素/秒控制速度，或按总时长控制整段运动；
- 滑入时间、滑出时间；
- 垂直显示起点/终点、轨道间距、最大同屏条数。

事件到来时由独立轨道管理器从顶部开始寻找入口：固定速度模式下，上一条弹幕尾部完全进入屏幕后即可安全复用顶部轨道；顶部入口仍被占用时才逐行向下。固定总时长模式采用更保守的整段占用，避免不同长度弹幕发生追尾。位移和透明度动画继续由 Web Animations API 执行，窗口本身不拦截鼠标时，直播软件与游戏仍可正常接收点击。

## 3. 侧边事件栏参数

- 事件类型过滤；
- 首次打开位置、窗口宽度与高度，以及新消息从顶部或底部进入；
- 头像、鼠标穿透与编辑定位；防溢出固定启用，不再暴露可关闭的开关；
- 每一种事件的强调色；
- 字体族、字号、粗细、文字色与昵称色（默认 #66CCFF）；
- 事件行只呈现头像、昵称和事件正文；无类型 Tag、UID、时间及多余边框；
- 低透明度渐隐底色、玻璃模糊和最多 6px 小圆角；窗口与消息列表外壳始终保持纯透明；
- 最大保留事件数、单条停留时间、滑入时间、滑出时间与滑动距离。

默认事件行不绘制边框，使用圆形头像和单句“昵称 + 事件”排版。新消息默认从窗口下方进入，也可切换为从上方进入；动画包含纵向滑入、轻微回弹和去模糊，退出时沿内容流方向淡隐。系统启用“减少动态效果”时动画时长自动归零。

“首次打开位置”只在本机尚未保存侧边事件栏坐标时生效；拖动并保存过位置后，后续启动优先恢复保存的显示器与坐标。

开启“编辑定位模式”后，窗口会临时关闭鼠标穿透，绘制 2px 蓝色边界和当前宽高；按住边界或空白区域即可触发 Tauri 原生拖动。每次松手后立即选择目标显示器并执行防溢出，退出编辑模式后恢复用户原先的穿透设置。滑动速度由滑动距离与滑入/滑出时间共同决定。

## 4. 使用流程

1. 先在 **连接设置** 登录并在 **播报台** 连接直播间。
2. 进入 **悬浮组件**，分别配置全屏弹幕和侧边事件栏。
3. 点击 **打开并预览**，bilimaku 会创建真实透明窗口并注入一组样例事件。
4. 用主窗口中的参数继续调整；设置会自动保存并实时同步到已打开窗口。
5. 开播时建议开启鼠标穿透；结束后在参数页点击关闭对应窗口。

设置会先在前端缓存，并同步进入 Rust 统一 `config.json` Store；模型与直播连接逻辑不依赖悬浮层。后续新增 OBS 浏览器源或主题预设时，可继续复用同一组领域事件和设置类型。

## 5. 多显示器定位与防溢出

- Windows 与 macOS 都把显示器排列抽象为一个全局虚拟桌面；副屏位于主屏左侧或上方时，坐标可以为负数。
- Tauri 后端读取所有显示器的物理坐标、DPI 缩放倍率及排除任务栏/Dock 后的 `workArea`，定位计算始终使用物理像素，避免混合 DPI 跳变。
- 原生拖动过程中不做实时夹取，让窗口可以自然跨越屏幕边界；松手后按窗口与各屏幕工作区的相交面积选择目标屏，完全悬空时改选距离最近的屏幕。
- 防溢出始终启用：只把窗口夹取到目标屏的 `workArea`，而不是虚拟桌面的外接矩形。后者在错位排列的显示器之间可能包含实际不存在的“空洞”。
- 持久化的是相对目标屏可移动区域的 `xRatio / yRatio`，并附带显示器名称和保存时原点。分辨率、缩放或排列变化后会重新计算物理位置；原显示器消失时回退到主屏。
